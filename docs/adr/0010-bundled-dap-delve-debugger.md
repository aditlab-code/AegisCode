# 0010. Bundled DAP Debugger (Delve) and Interactive Debug Proxy

We decided to implement step-by-step Go and backend debugging in AegisCode using the standard Debug Adapter Protocol (DAP) powered by Delve (`dlv dap`). Rather than bundling bloated architecture-specific debugger binaries or relying on heavy IDE extension runtimes, the Go Core Server supervises a native `dlv` process out-of-process via the Process Supervisor (ADR 0004) with dynamic host toolchain resolution (`exec.LookPath("dlv")`) and a 1-click installation notification fallback. Communication with Delve is established over ephemeral localhost TCP sockets (`127.0.0.1:<port>`), while the Core Server acts as a lightweight DAP client proxy, translating AegisCode REST endpoints (`/api/v1/debug/*`) and Server-Sent Events (`/api/v1/events/debug`) into DAP JSON-RPC transactions. A strict fail-safe process group teardown (`SIGTERM` + watchdog `SIGKILL`) is enforced on session termination to guarantee zero orphaned Delve processes or locked TCP ports, maintaining a sub-30MB server baseline footprint and synchronized debug inspection across Desktop Web and Remote Tablet Companion.
